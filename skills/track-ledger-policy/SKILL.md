# 트랙 원장 — 다중 세션·다중 레포 작업 순서 정책

이 파일은 `~/.claude/CLAUDE.md` 에서 항상 로딩된다. **어느 위치에서 Claude Code 를 켜도 적용된다.**

**목적:** 여러 세션이 여러 레포에서 동시에 도는 작업에서, "지금 무엇을 먼저 해야 하는지"와
"누가 무엇을 쥐고 어떤 결론을 냈는지"를 사람의 기억과 손으로 고치는 문서가 아니라 시스템이 들고 있게 한다.

---

## 1. 언제 트랙을 만드나 (트리거)

다음 중 **둘 이상**에 해당하면 트랙을 제안한다:

- **레포가 2개 이상** 걸린다 (워크트리 분리 포함)
- **세션이 2개 이상** 붙는다 — 또는 붙을 예정이다
- **순서 있는 게이트가 3개 이상** — 머지 / apply / 배포 / 릴리즈 / 공지
- **하루 안에 안 끝난다**

만들지 **않는다**: 한 레포·한 세션에서 끝나는 작업, 순서가 자명한 작업, 게이트가 1~2개인 작업.
그런 것은 원장 task 문서(`## 작업 큐`의 `S-n` 슬라이스)로 충분하다.
**트랙은 조율 객체다 — 조율할 것이 없으면 순수한 부담이다.**

## 2. 만들기 전에 반드시 확인

```bash
track list --repo <현재 레포>      # 이 레포에 이미 걸린 트랙이 있나
```
있으면 **새로 만들지 말고 붙는다** — `track join`. 트랙이 갈라지는 순간 이 시스템의 의미가 사라진다.

## 3. 불변 규칙 — 이것만은 예외 없다

| 규칙 | 이유 |
|---|---|
| **상태는 손으로 쓰지 않는다** | 완료 여부의 진실은 문서가 아니라 GitHub·AWS·git 에 있다. 스키마에 `status` 필드가 아예 없다 |
| **보고는 상태를 바꾸지 못한다** | 세션 보고는 `track signal` 로 신호 로그에만 남는다. 상태는 프로브만 쓴다 |
| **모르는 것은 미검증으로 남긴다** | 완료로도 미완료로도 반올림하지 않는다. 2값이면 "확인 못 했다"가 반드시 한쪽으로 기운다 |
| **프로브는 읽기 전용** | `aws get-/describe-/list-` · `git` 읽기 · `gh` GET 만. 쓰기 동사는 실행 자체가 거부된다 |
| **원격을 직접 묻는다** | 로컬 `origin/*` 는 다른 세션의 fetch·gc 로 움직인다. `gh api` 로 GitHub 를 직접 읽는다 |

## 4. 계획에는 **왜 이 순서인지**를 쓴다

`needs:` 는 기계가 읽는 의존이고, `note:` 는 사람이 읽는 **게이트 근거**다.
`needs` 만 있으면 "의존이 있다"는 사실만 남고 이해가 사라진다. 예:

> `note:` 게이트 — 의존 게이트가 없어 보이지만 있다. **dev 와 stage 는 형제라 dev 머지가 stage 로 이어지지 않는다.**

팀에 요청·공지·중단이 필요하면 `team:` 에 한 줄로. `track impact` 가 그것만 모아 보여준다.

## 5. 세션 간 대화 — 이때만 보낸다

① 스텝 상태가 실제로 움직였을 때(관측, 추정 아님) ② 결정이 서거나 뒤집혔을 때
③ 보드에 없는 선행이 새로 생겼을 때 ④ 막힌 것이 풀렸을 때 ⑤ 내가 남의 실측을 뒤집었을 때
예외) plan 에 예상 밖 항목이 섞여 오너 결정이 필요할 때

**보내지 않는 것**: 진행 경과 · 같은 사실 재설명 · 상대 원장에 이미 있는 내용.
그런 것은 원장에 신호로 남기고 필요한 세션이 `track brief` 로 당겨 간다.

## 6. 결정은 원장에, 교차 링크는 mirrors 로

세션마다 자기 결정 원장(`ledger decide`)을 갖는다. 같은 사안을 두 원장이 각자 적으면
한쪽이 뒤집혀도 다른 쪽이 모른다. 새 결정이 다른 원장의 결정과 같은 사안이면:

```bash
ledger decide --file <내 task> --topic <slug> --title ... --body ... \
  --mirrors <상대 task 접두사>:D-n
```
링크 대상이 폐기되면 `track conflicts` 가 "한쪽만 폐기"로 잡고 후속까지 알려 준다.

## 7. 명령 요약

```
track list [--repo X]   이 레포에 걸린 트랙이 있나        track next     지금 할 것 한 줄
track verify            프로브 일괄 실측 (상태의 유일한 작성자)  track ls       전체 큐
track probes --audit    프로브가 거짓 양성을 낼 수 있나      track impact   팀에 요청할 것만
track join --session X --steps T-2   자기 등록 + 브리프    track brief    그 세션이 알 것만
track signal --step T-2 --kind merged --evidence <해시>   track conflicts 교차 원장 점검
track serve             실시간 UI (기본 127.0.0.1:4747)
```

절차·스키마 상세는 `/track-ledger` 스킬에 있다. 트랙을 처음 만들 때 그 스킬을 부른다.
